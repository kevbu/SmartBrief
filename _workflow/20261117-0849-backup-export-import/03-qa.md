# QA: Backup export and import

> Spec: [01-spec.md](01-spec.md) · Date: 2026-11-17

## QA fixture
Dev server `next dev -p 3102` on throwaway SQLite files in the session scratchpad (never the live DB, never port 3000).
- DB A: prefs (`constructive`, sessionSize 25, `pushEnabled: true`), AppState with VAPID keys, one PushSubscription, BBC weight 1.3, science weight 0.7, saved article a1, unsaved a2–a4, saved story s1 → [a1, a2] (createdAt 07:00), unsaved story s2.
- DB B ("other machine"): article `LOCAL2` with A's a2 URL, BBC weight 0.5, current batch story `cur` (createdAt 06:00). `SMARTBRIEF_PASSWORD` set to a generated test value.
- DB C: empty schema.

Extra checks:
- Auth: with `SMARTBRIEF_PASSWORD` set, unauthenticated GET export and POST import → 307 to `/login`.
- Atomicity: file with a new weight `ATOMIC` + an invalid article → error, `ATOMIC` not written (before the schema pre-check existed, so this exercised the transaction rollback itself).
- `pushEnabled` not imported (B stays `false`); B's AppState/PushSubscription counts stay 0.
- Feed batch: after import into B, `/api/news` top stories = [`cur`]; imported s1 createdAt clamped to 05:59:59.999.

## Scenarios Deliberately Not Added
- Gherkin/e2e: `e2e/` is outside this run's file surface. Coverage is unit tests + manual HTTP/browser checks above.
- Real file-picker click: the Browser pane cannot drive a native file dialog. The import was driven by setting `input.files` via DataTransfer and dispatching `change`, which runs the same React handler.
- Light theme screenshot: same tokens as sibling sections; not separately captured.

## Implementation Issues Found
- Prisma error messages were multi-line with the whole query. Fixed: the route returns the last line only.
- Success note said "saved items already present" while counting referenced articles too. Fixed: "already present".
