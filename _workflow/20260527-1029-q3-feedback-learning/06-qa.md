All 12 ACs are routed away from Gherkin — correct because there is no e2e framework. Specific routing rationale:

- **AC1, AC2, AC4, AC6** — pointer/mouse timer behavior requires device interaction at sub-second resolution; not meaningfully testable without a live browser automation framework
- **AC3** — tap vs. hold distinction is a timing-based interaction; manual simulation is the right venue
- **AC5** — `article.reason &&` falsy guard is a static code pattern verified by TypeScript strict mode at build time; no runtime test needed
- **AC7, AC8** — no-regression claims for untouched code paths; code inspection is sufficient (reading the diff is the test)
- **AC9, AC12** — removal of code; confirmed by grep; no runtime behavior to exercise
- **AC10** — visual section presence; manual scroll
- **AC11** — verified by build pipeline output

## Manual Test Cases

Run these against `npm run dev` (http://localhost:3000) with a populated database (requires ≥ 1 article with `article.reason` set — trigger by giving a few "More like this" feedbacks so the learning system generates reason strings).

### MT-1 — Desktop hover shows chip after 300 ms

**Setup:** Skim mode (default), article with a reason string visible on screen.

| Step | Action | Expected |
|------|--------|----------|
| 1 | Move mouse over article card | Nothing happens immediately |
| 2 | Hold mouse still for < 300 ms, then move away | No chip appears |
| 3 | Move mouse over same card, hold still for ≥ 300 ms | Chip appears below description: `✦ <reason>` |
| 4 | Move mouse off card | Chip disappears immediately |

**Pass condition:** Chip appears on step 3, absent on steps 2 and 4.

---

### MT-2 — Mobile long-press shows chip after 500 ms

**Setup:** Chrome DevTools → Toggle device toolbar → iPhone 14 Pro (or similar). Skim mode, article with reason visible.

| Step | Action | Expected |
|------|--------|----------|
| 1 | Tap and immediately release (< 500 ms) | Article opens normally, no chip |
| 2 | Press and hold for ≥ 500 ms without moving finger | Chip appears below description |
| 3 | Release after chip is visible | Chip remains visible |

**Pass condition:** No chip on quick tap; chip on 500 ms hold.

## Edge Cases and Risks

| Risk | Severity | Notes |
|------|----------|-------|
| Chip renders when `article.reason` is `""` (empty string) | Low | `""` is falsy in JS — the `article.reason &&` guard correctly prevents render. Verify if any article has `reason: ""` vs `reason: undefined` — both are handled. |
| `onPointerCancel` not firing on some Android browsers | Low | `handlePointerUp` is wired to both `onPointerUp` and `onPointerCancel` — covered. |
| Hover timer fires after component unmounts | Low | Cleanup `useEffect` (lines 87–92) clears both `pressTimerRef` and `hoverTimerRef` on unmount — covered. |
| Chip visible in deep mode when switching from skim | Low | `depthMode === 'deep'` branch takes priority — chip branch is `else if`, so it can never render in deep mode. |
| `shortenReason` called with `article.reason` when it's `""` | Not applicable | The outer `article.reason &&` guard prevents reaching `shortenReason` with a falsy value. |
| Settings page state from removed vars causes TS "used before assigned" | Not applicable | Build confirmed clean — no dangling references. |
